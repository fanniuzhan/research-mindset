# 科研数据处理思维

让每个关键处理决定都能回答：**为了哪个问题，依据什么改变了数据，改变后代表谁，怎样知道没有把结论做出来？**

以数据为证据，以处理为可检验的科学选择。允许探索改变问题，但保留修改理由与原有证据。来源与理论依据见 [references/source-basis.md](references/source-basis.md)，仅在用户需要解释依据或延伸阅读时读取。

## 按任务选择深度

- **思路／规划：** 利用已有背景构造最小分析路径，明确待验证假设；没有实际数据时只提出检查，不编造检查结果。
- **审计／实施：** 先读数据字典、协议、代码与小样本，再做能影响当前决定的检查。将发现转成可复现修正并验证。
- **异常／结果解读：** 回溯原始实例、处理链与分组分布，区分实现错误、测量问题、选择效应和真实现象，再安排区分性检查。

简单问题只执行相关步骤。已有可信证据直接复用，不为填模板重复采集。沿用用户指定语言和工具；不因为本 skill 改换框架。缺少关键背景时，先做独立可推进的检查，只询问会改变处理决定的缺口。

## 1. 把处理动作连到研究问题

先用非模型语言写明：研究谁／什么现象，希望了解或改善什么，这次处理要支持哪个判断。区分描述、探索、预测与因果解释，匹配所需证据。

分开 **真实研究目标、可观测测量／代理标签、训练或分析目标、成功证据**。做一次 Oracle Test：即使这次处理或模型目标完美完成，能支持哪条科学结论？不能支持时，补上验证桥梁或收缩主张。

确定目标总体、可访问范围、最终样本与时间／空间范围。现成数据允许先探索再细化问题；不能悄悄把事后发现改写成事先成功标准。纯机制探索不必强行提出产品部署目标。

## 2. 先懂记录，再处理数值

查清谁采集、原始目的、测量工具、协议、版本和既往转换。明确 **一行／文件代表什么**，以及观测、抽样、处理和推断分别以什么为单位。按需要保存来源到独立对象再到派生样本的层级。

逐源核对字段定义、单位、时钟、标签依据与缺失编码。同名字段不保证同义，相同 tensor 形状不保证测量可比。ID 需考虑来源命名空间；记录 ID 不等于独立对象 ID。身份缺失时，明确无法验证的重叠与推广条件。

先写期望的输出结构和关键约束：粒度、键、单位、可取值、连接关系及数据何时可用。必要时用模拟小样本检验接口；模拟结构不证明真实测量有效。

## 3. 检查生命体征并回到实例

检查与当前问题有关的对象数、记录数、时长／暴露量、缺失、重复、失败、标签和数值范围；查看分布与按时间变化，按来源及关键对象分组。每个比例同时给分子、分母和统计单位。

选择正常、极端、缺失、失败和边界实例，追踪从原始记录到分析输入的解释是否正确。重点核对三类证据：

- **有效性：** 类型、值、单位及范围是否符合协议与领域知识？
- **内部一致性：** 时间顺序、总分与分项、跨字段约束、键与粒度是否一致？
- **外部一致性：** 与独立来源、协议和历史结果是否吻合；不吻合有无可检验解释？

“官方数据”“读取成功”“值落在范围内”不能替代这三类检查。关注稀有但重要的失效模式，不将字段近乎常数直接等同于没有价值。

## 4. 让每次转换成为可审计的决定

实施前说明处理目的和依据。保留原始数据，生成可追溯派生输出；未经授权不覆盖原始或既有结果。记录转换代码／参数／版本，以及关键输入、输出和排除原因。

按动作检查语义：

| 动作 | 最重要的追问 |
|---|---|
| 筛选／质量排除 | 排除了谁？错误还是实际罕见状态？目标总体是否改变？ |
| 连接／聚合 | 键是否唯一？粒度是否变化？有没有多对多膨胀、未匹配丢失或重复计权？ |
| 去重 | 重复的是导出记录、测量还是独立对象？凭哪些字段与内容确认？ |
| 缺失／填补 | 未测、未记录、不适用、隐私隐藏、处理失败如何区分？填补假设和不确定性是什么？ |
| 单位／时间／信号变换 | 前后测量是否一致？有没有时钟、边界或任务信息损失？ |
| 特征／标签构造 | 它测量了什么？是否与目标循环定义或使用了未来信息？ |

零、未知与不适用分开处理；用可观测证据支持推断式填补。对重要处理前后核对对象数、样本数、暴露量与群体构成。优先做小样本端到端迭代，逐步覆盖特殊来源；容易处理的子集不能未经说明代表全体。

## 5. 用异常提出竞争解释

先排查自己的代码、连接、单位、日期与分母，再考虑采集机制和真实差异。异常是调查入口，不是默认删除理由。

对会改变结论的异常，写出合理的竞争解释、各自预期证据以及最低成本的区分性检查。可采用原始样本复核、交叉来源验证、分组比较、阈值敏感性或小型对照实验；一次只改变足以区分解释的关键因素。

EDA 每发现一个模式，都回答“它改变了什么判断，下一步需要什么证据”。保存探索选择；描述关联时不越界写成原因。确认性结论需要与发现过程相匹配的独立数据、设计或统计校正，不能用大量切片寻找最漂亮的结果。

## 6. 按使用目标组织抽样与验证

排错抽样与总体估计服务不同目的：可多看风险样本找问题；若估总体问题率，需定义总体与分母，保留覆盖范围、概率抽样设计、入样概率及审核失败，使用与设计匹配的估计和区间。事后加权不能自动修复未知选择机制；方便挑选的样本不能直接给总体比例。

验证划分匹配“未来是什么”：未见对象、会话、时间、来源或任务。关联不一定是泄漏，但共享对象、重复记录、重叠片段及未来信息要分别检查。先确定原始对象所属划分，再派生样本；从数据学习的标准化、填补、特征选择与校准在训练部分／训练折内拟合。数据审计可以检查测试集的完整性与泄漏，但不利用测试标签或表现选择处理方案。

模型选择与最终评估分开。汇总权重服务目标总体，必要时同时看样本、对象与来源等权结果。区间与比较保留依赖结构；种子波动不替代对象抽样不确定性，高相关不保证测量一致，标注一致不保证效度，指标提升不自动证明机制正确。

## 7. 将证据转成下一步决定

使用简单基线或最小流程检验处理是否必要。关键规则做与目标有关的敏感性检查，关注分组与失败模式。若改善只来自排除困难人群、重复计权或测试信息，修正流程和主张，不将其包装成方法优势。

明确当前不确定性主要来自样本变异、测量／代理含义、还是使用条件变化；缩窄区间不能解决后两类。证据不足时，输出条件化判断与下一项最有区分力的检查，不凭“数据噪声大”结束分析。

## 输出与按需参考

先给当前判断和直接行动，再呈现必要证据。按任务规模选用 [references/decision-sheet.md](references/decision-sheet.md) 中的问题页、处理决策账本、流失表或异常工作表；不强制生成全套文档。

最小结果应让用户看清 **已观察事实、暂时解释、处理决定、未解决条件与下一步验证**。未运行的检查标注“拟做”，未核实的假设标注“待验证”；不能用勾选清单冒充执行证据。简单工作可在几句话或一个小表内完成。

处理 EEG／HEEDB 或其他多设备生理信号时，读取 [references/eeg-transfer.md](references/eeg-transfer.md)。按具体任务取舍，先复核测量和依赖，再决定是否需要模型创新。
