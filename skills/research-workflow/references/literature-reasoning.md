# 文献阅读、已有方法的理论分析与问题导向综述

按当前任务阅读：1. 精读、粗读与引用追踪；2. 已有方法与 research gap 的理论分析；3. 综述结构；4. 挑战、创新与证据。

## 1. 用少量精读和广泛粗读建立方向认知

默认先精读 3–4 篇代表论文，其余广泛粗读。选择能帮助理解主要路线和当前瓶颈的高质量工作，例如奠基论文、方法机制清楚的代表作和重要后续修正；不必固定配额。高被引是发现候选的线索，不能代替对问题、方法、证据和相关性的判断；近期重要工作也可能尚未积累引用。

粗读围绕明确问题查看摘要、关键图表、方法概览和结论，必要时核对实验条件与局限，用来定位路线、相关性、分歧和需要精读的证据。精读应能复述其研究问题、设计理由、目标与假设、方法机制、关键推导、实验对照、实际结论和适用边界；关键瓶颈涉及附录时继续核查。阅读范围如实记录。

围绕精读论文双向追踪：

- **向后追溯参考文献：** 确认问题、思想、假设和技术分别从哪里来；阅读相关原文后再判断 idea 来源，不能把所有被引工作都视为直接启发。
- **向前追踪引用它的论文：** 找后续改进、独立验证、负面结果、争议和边界研究；引用关系本身不表示赞同或证实。记录追踪日期与范围。

当能够解释主要路线的关系与差异、复述代表方法的机制与边界，并定位影响研究选择的关键未知时，可以形成阶段性认知。若某个 gap 的关键依据未核实、漏掉重要替代路线或存在相互冲突的证据，针对性补读；不以凑足篇数或无限扩张文献表为目标。

## 2. 对已有方法与 research gap 做充分的理论分析

分析对象先是当前方向的代表性路线，再是与候选 gap 直接相关的方法。先准确解释它解决了什么、为何可能有效，再分析边界；不能为了衬托自己的方法而缩窄基线能力。

### 分开回答三个问题

1. **为什么这样做：** 原始目标和设定是什么？可用信息、假设、目标函数、结构或约束如何使设计合理？它已经贡献了什么？
2. **为什么没做某件事：** 先核实确实未覆盖。可能是问题定义、任务范围或部署条件不同，也可能受信息、计算、数据、可辨识性或性能权衡限制。作者未交代原因时，写“未说明”；我们的解释标为分析或假设，不代替作者表达意图。没有不可行性证据时，不声称别人做不到。
3. **为什么效果受限：** 指明在哪种任务、数据、资源、指标或泛化条件下出现什么后果，再分析产生后果的机制。区分表达能力、可用信息、学习目标、优化、样本量、分布变化、实现和评价设计等来源；只分析有线索的因素，不机械罗列所有可能原因。

### 建立可审查的机制链

> 问题设定与目标 → 方法依赖的假设 → 方法通过什么机制起作用 → 哪些条件使假设或机制失效 → 可观察后果 → 对上位问题的影响。

理论分析要与问题相称：可以是有明确前提的数学推导、可辨识性或信息分析、反例、边界情形、目标与评价不一致的分析，也可以是可检验的机制解释。不为显得“理论充分”而编造定理或加入无关公式。推导写清前提和适用范围；机制解释没有被检验时保留假设状态。

例如，“未显式建模长时依赖”不足以推出“无法使用长时信息”。应核查有效输入范围、状态或聚合机制、训练信号及任务真正需要的信息；若要主张在某条件下信息不可用，需要说明哪些观测对方法不可区分、目标却不同，或提供相应证据。若只是有限样本或训练造成的表现问题，就不能提升为表达能力上的不可能。

每个关键判断保留依据：

- **作者主张：** 原文、页码、章节或公式位置；不自动作为成立事实。
- **已有理论或实验证据：** 来源、设定和实际支持范围。
- **我们的分析：** 推理链、前提及能解释哪些观察。
- **待检验解释：** 可区分竞争解释的预测与检验方案。

一个分数差异不能独立证明机制。比较前核查任务、推理可用信息、数据划分、监督、资源、调参与评价是否可比，排除直接影响判断的实现和优化问题。机制检验可按需采用受控干预、条件分组、敏感性分析、诊断任务或反例；整体指标提升和消融本身通常不足以唯一确立机制。也寻找反证：同类方法是否已在相同条件下克服该瓶颈，或者简单改动就能消除它？

### 从方法边界推导 gap

一个可用于 motivation 的 gap 至少应说明：

- **具体是什么：** 在明确条件下，哪个重要目标仍未被充分实现或理解？
- **为什么存在：** 现有路线的假设、机制或约束如何造成这个边界？哪些属于设计选择，哪些有更强的限制依据？
- **为什么值得解决：** 它如何影响上位问题或实际目标，而非仅缺少某个模块？
- **为什么不容易：** 直接扩展、已有替代方法或简单基线为何不足，会遇到什么权衡？证据不足就写待核实。
- **如何推进与检验：** 新方法改变哪个环节，为什么可能有效；哪些结果会支持、削弱或推翻这个判断？

gap 可以是重要机制未知、成立条件不清或评价证据不足，不必总是方法性能缺陷。没有读到、作者 future work、未组合两种方法，都不能单独确立 gap；文献中没有找到明确解释，也不是已经证明其不存在。

## 3. 综述展示对方向的认知体系

围绕上位问题及其子问题组织研究系列。对每个有意义的路线说明：试图回答什么 → 为何采用这类设计 → 已取得什么进展 → 依赖哪些条件 → 仍存什么关键问题。比较路线之间的共同假设、互补关系、演进和争议，而非依次写“论文 A 做了什么，论文 B 做了什么”。

可用的段落逻辑：

> 为解决【子问题】，现有研究形成【主要路线及引用】。它们通过【机制】取得【有证据的进展】，但在【条件】下依赖的【假设】受到限制，导致【后果及证据】。已有改进【回应了什么及剩余边界】，因此本研究聚焦【重要且仍未充分回答的问题】。

按实际证据使用这段逻辑，不强迫所有路线有同一缺陷。引用放在对应判断附近，涉及机制和边界的核心主张回到原文；避免把某篇论文的局限推广到整个方向。

## 4. 挑战、创新和证据的对应

论文和汇报中，凡承诺解决的挑战都要有回应；每项核心创新都应解释它为何必要、如何起作用，以及由什么证据支持。对应是逐项覆盖，允许一对多或多对一。

| 本文承诺的挑战及条件 | 已有方法受限的依据 | 对应创新或方法改变 | 预期作用机制与可检验预测 | 验证设计 / 实际证据 | 已解决、部分缓解或待验证 / 边界 |

| 按实际课题填写 | 区分文献、推导与假设 |  |  | 计划与结果分开 |  |

领域宏观背景可以讨论更广的问题，但明确哪些不属于本文目标。发现表中未对应的挑战，补充必要方法和检验，或缩小主张并交代局限；不要为表格完整而编造贡献。仅部分缓解时说明程度和条件，不写为全面解决。发现没有问题依据的“创新模块”，重新判断其必要性及是否有独立知识价值。

将一致性检查用于 proposal、论文、摘要、贡献列表、research highlight 和汇报的关键改动，不要求每次普通讨论都生成表格。
